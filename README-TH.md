# Monthly Sales Forecast Assistant

แดชบอร์ดยอดขายและเครื่องมือคาดการณ์ความต้องการเดือนถัดไป (ไทย/อังกฤษ) สำหรับโรงงานผลิตหลังคาเหล็กและฉนวนพียูโฟม อ่านไฟล์ส่งออกจากโปรแกรมบัญชี Express ทั้ง 3 รายงาน (ขายเงินสด ขายเงินเชื่อ ใบรับมัดจำ) โดยตรงในเบราว์เซอร์ แล้วแปลงเป็นการคาดการณ์ มุมมองสินค้าขายดี/วันสต็อกพอใช้ และรายงานทีมขาย/ลูกค้า — ไม่มีการอัปโหลดข้อมูลใด ๆ ไปยังเซิร์ฟเวอร์

โปรเจกต์งานเวิร์กชอปมหาวิทยาลัย ("Vibe Coding")

## 1. วิธีใช้งาน

**เว็บไซต์จริง:** [kisstk322.github.io/Monthly-Sales-Forecast-Assistant](https://kisstk322.github.io/Monthly-Sales-Forecast-Assistant/)

ที่อยู่ด้านบน (ไม่ต้องใส่ `/index.html`) ให้บริการโดย GitHub Pages และได้ตรวจสอบแล้วว่าใช้งานได้จริง (`HTTP 200`) ก่อนเขียนเอกสารนี้ไม่นาน เปิดลิงก์ เลือกบทบาทที่หน้าต้อนรับ แล้ว (ในฐานะผู้บริหาร) นำเข้าไฟล์ CSV จาก Express ทั้ง 3 ไฟล์ได้จากแท็บ **ข้อมูลและสำรอง**

### หรือรันในเครื่องตัวเอง

ไม่ต้อง build และไม่มี dependency ใด ๆ เป็น HTML/CSS/JS ธรรมดา

```bash
git clone https://github.com/KissTK322/Monthly-Sales-Forecast-Assistant.git
cd Monthly-Sales-Forecast-Assistant
npx serve -l 8000
# หรือ: python -m http.server 8000
```

จากนั้นเปิด `http://localhost:8000` Service worker จะไม่ทำงานถ้าเปิดไฟล์ด้วยการดับเบิลคลิก ต้องเปิดผ่าน `http://` หรือ `https://` เท่านั้น

เพิ่มเติม: `node build.cjs` รวมทุกไฟล์เป็น `dist/index.html` ไฟล์เดียวสำหรับใช้งานออฟไลน์ (บิลด์นี้ไม่มี service worker) ส่วนชุดทดสอบอัตโนมัติรันด้วย `node --test tests/*.test.cjs` — มีทั้งหมด 30 เทสต์ และผ่านทั้งหมดในขณะนี้

## 2. บทบาทผู้ใช้

เลือกที่หน้าต้อนรับก่อนที่ข้อมูลยอดขายใด ๆ จะแสดง รหัสผ่านของแต่ละบทบาทถูกแฮชด้วย PBKDF2-SHA256 จำนวน 600,000 รอบ และเก็บไว้ใน `localStorage` ของเบราว์เซอร์นั้นเท่านั้น ไม่มีการส่งไปที่ใด — ถ้าเปลี่ยนเบราว์เซอร์หรือเครื่อง ต้องตั้งรหัสผ่านใหม่

| บทบาท | สิทธิ์การเข้าถึง |
| --- | --- |
| **พนักงานขาย** | เลือกรหัสพนักงานขายของตนจากข้อมูลที่นำเข้าแล้ว และตั้งรหัสผ่าน 6 ตัวอักษร เห็นเฉพาะยอดขายของตนเอง (แท็บ "ยอดขายของฉัน") นำเข้าข้อมูลไม่ได้ |
| **หัวหน้าฝ่ายขาย** | เห็นทุกอย่างยกเว้นแท็บข้อมูลและสำรอง: ภาพรวม คาดการณ์ สินค้า ทีมขาย ลูกค้า ของพนักงานขายทุกคน รหัสผ่านอย่างน้อย 12 ตัวอักษร นำเข้าหรือแทนที่ข้อมูลไม่ได้ |
| **ผู้บริหาร** | เห็นทุกอย่างเหมือนหัวหน้าฝ่ายขาย บวกแท็บข้อมูลและสำรอง: นำเข้า CSV จาก Express ดาวน์โหลด/กู้คืนไฟล์สำรอง JSON และจัดการสินค้า/ลูกค้า/พนักงานขาย รหัสผ่านอย่างน้อย 12 ตัวอักษร |
| **ทีมเทคนิค** | หน้าจอเดียวคือ "ดูแลรหัสผ่าน" สำหรับรีเซ็ตรหัสผ่านของหัวหน้าฝ่ายขาย ผู้บริหาร หรือพนักงานขายรายบุคคล บนเบราว์เซอร์นั้น ไม่มีสิทธิ์เข้าถึงข้อมูลยอดขาย สินค้า หรือลูกค้าใด ๆ และการรีเซ็ตรหัสผ่านไม่ได้ทำให้เห็นรหัสเดิม |

## 3. การนำเข้าข้อมูล

เฉพาะบทบาท **ผู้บริหาร** เท่านั้นที่นำเข้าข้อมูลได้ จากแท็บ **ข้อมูลและสำรอง** ใช้ "นำเข้า CSV จาก Express" แล้วเลือกไฟล์รายงานทั้ง 3 ไฟล์พร้อมกัน (หรือเพิ่มทีหลังก็ได้ — ดูด้านล่าง)

ระบบตรวจชนิดไฟล์จากชื่อรายงานที่พิมพ์อยู่ในเนื้อไฟล์ ไม่ใช่จากชื่อไฟล์:

| ข้อความที่พบในไฟล์ | ถูกจัดเป็น |
| --- | --- |
| `รายงานขายเงินสด` | ขายเงินสด |
| `รายงานใบกำกับสินค้า` | ขายเงินเชื่อ |
| `รายงานใบรับมัดจำ` | ใบรับมัดจำ |

Express ส่งออกรายงานเหล่านี้ด้วยการเข้ารหัส Windows-874 (TIS-620 ภาษาไทย) ระบบนำเข้าจะถอดรหัสไฟล์ทั้งแบบ UTF-8 และแบบ Windows-874 แล้วให้คะแนนว่าผลลัพธ์ใดอ่านเป็นภาษาไทยที่สมเหตุสมผลมากกว่า และเลือกใช้ผลนั้นโดยอัตโนมัติ — ไม่มีตัวเลือกการเข้ารหัสให้ตั้งเอง

ก่อนนำข้อมูลไปใช้จริง จะมีกล่องยืนยันแสดงสิ่งที่อ่านได้ (จำนวนรายการขาย สินค้า ลูกค้า และเงินมัดจำ) และถามให้ยืนยันก่อนแทนที่แดชบอร์ดปัจจุบัน เพื่อไม่ให้ไฟล์ที่ผิดพลาดเขียนทับข้อมูลที่ดีอยู่โดยไม่รู้ตัว

**นำเข้าไฟล์ใบรับมัดจำภายหลังได้:** ถ้ามีข้อมูลขายเงินสดหรือขายเงินเชื่อโหลดอยู่แล้ว สามารถนำเข้าไฟล์ใบรับมัดจำใหม่เพียงไฟล์เดียวในภายหลังได้ — ระบบจะรวมเข้ากับชุดข้อมูลเดิมแทนที่จะต้องเลือกไฟล์ทั้งหมดใหม่ แต่ไฟล์ใบรับมัดจำเพียงอย่างเดียวไม่สามารถใช้ "เริ่ม" ชุดข้อมูลใหม่ได้ เพราะไม่มีวันที่ขายไว้กำหนดเดือนที่จะรายงาน

ไฟล์สำรอง JSON (ดูข้อ 6) นำกลับเข้ามาผ่านตัวเลือกไฟล์เดียวกันนี้ได้เช่นกัน

## 4. ฟีเจอร์หลัก

- **คาดการณ์ความต้องการ (หลัก: ระดับกลุ่มสินค้า)** สินค้าถูกจัดกลุ่มตามรหัส 2 หลักแรก สำหรับแต่ละกลุ่ม แบบจำลองคำนวณอัตราการใช้รายเดือนแบบถ่วงน้ำหนักพร้อมแนวโน้มแบบหน่วง โดยเลือกช่วง 3 หรือ 6 เดือนต่อกลุ่มด้วยการทดสอบย้อนหลัง **ค่าคลาดเคลื่อน WAPE จะแสดงคู่กับตัวเลขเสมอ** ให้เกรดเป็นดี/พอใช้/อ่อน/ใช้ไม่ได้ แต่ค่าคลาดเคลื่อนสูงจะไม่ทำให้ตัวเลขถูกซ่อน กลุ่มต้องมีการขายในประมาณหนึ่งในสามของเดือนที่นำเข้าทั้งหมดจึงจะมีตัวเลขให้ ถ้าน้อยกว่านั้นระบบจะบอกเหตุผลแทนการเดา แผนที่ความร้อนรูปแบบการขายรายเดือน (หนึ่งแถวต่อหนึ่งกลุ่ม คอลัมน์ตามจำนวนเดือนที่มีข้อมูลจริง ไม่ตายตัว) แสดงคู่กับป้ายคลาสดีมานด์ที่ได้
- **สินค้าขายดีพร้อมวันสต็อกพอใช้ (C1)** จัดอันดับกลุ่มสินค้าตามจำนวนหรือยอดขายในช่วงวันที่เลือก พร้อมเส้นเล็กแสดง 6 เดือนล่าสุด กรอกยอดสต็อกต่อกลุ่มเพื่อดูวันที่สต็อกพอใช้ ถ้าไม่กรอกระบบจะไม่สมมติค่าใด ๆ และตัวเลขนี้จะไม่ถูกบันทึกข้ามเซสชัน
- **การคาดการณ์ระดับ SKU (ตารางอ้างอิงเท่านั้น)** การคาดการณ์รายสินค้าเดิมยังแสดงอยู่ แต่ระบุชัดเจนว่าไม่น่าเชื่อถือ — วัดค่าคลาดเคลื่อนได้ประมาณ 78% กับข้อมูลจริง — ให้ใช้การคาดการณ์ระดับกลุ่มด้านบนแทน
- **สินค้า** สัดส่วนยอดขายตามกลุ่มสินค้า อันดับ 5 อันดับแรก (ตามยอดขายหรือจำนวนภายในหน่วยเดียวกัน) ตารางรายละเอียดสินค้าที่ค้นหาได้ และการจัดอันดับตามคุณสมบัติที่วิเคราะห์ได้ (ลอน สี ความหนา) จากคำอธิบายรายการสินค้า
- **ทีมขาย** ยอดรวมรายพนักงาน เมทริกซ์พนักงานขาย × กลุ่มลูกค้า และแผนที่ความร้อนเมทริกซ์พนักงานขาย × กลุ่มสินค้า
- **ลูกค้า** สัดส่วนยอดขายตามบริษัทลูกค้า และอันดับลูกค้าที่ค้นหา กรอง และแบ่งหน้าได้
- **ภาพรวม** ตัวชี้วัดหลักและแนวโน้มสำหรับผู้บริหารและหัวหน้าฝ่ายขาย

รหัสกลุ่มสินค้าจับคู่กับตารางชื่อในตัวชุดเล็ก ๆ กลุ่มใดที่ไม่มีในตารางจะแสดงหมายเหตุว่าชื่อเป็นการตั้งชั่วคราวและรอการยืนยัน

## 5. การติดตั้ง / ใช้งานออฟไลน์

แอปนี้เป็น PWA ที่ติดตั้งได้ (`manifest.webmanifest`, service worker แบบมีเวอร์ชันใน `sw.js`)

- **iPhone / iPad (Safari):** แชร์ → เพิ่มไปยังหน้าจอโฮม
- **Android / Windows / Mac (Chrome หรือ Edge):** ใช้ไอคอนติดตั้งในแถบที่อยู่ หรือเมนูเบราว์เซอร์
- **Mac (Safari):** เมนู File → Add to Dock

หลังจากเปิดครั้งแรก ตัวแอปจะโหลดได้แบบออฟไลน์ เมื่อมีการอัปเดตเวอร์ชันใหม่ จะมีแบนเนอร์ "โหลดใหม่" ขึ้นมาแทนการสลับเวอร์ชันเงียบ ๆ โดยไม่บอกผู้ใช้ และจะมีป้ายบอกสถานะเมื่อเบราว์เซอร์ไม่มีการเชื่อมต่อเครือข่าย

## 6. ความเป็นส่วนตัวและการเก็บข้อมูล

- ไฟล์ CSV ถูกอ่านจากเครื่องด้วย File API ของเบราว์เซอร์ และไม่ออกจากอุปกรณ์เลย — ไม่มีเซิร์ฟเวอร์ ไม่มีการเก็บสถิติการใช้งาน และไม่มี dependency ขณะทำงานที่พึ่งพาบริการภายนอกใด ๆ
- ทุกครั้งที่เปิดหน้าเว็บ แอปจะเริ่มจากชุดข้อมูลตัวอย่างในตัวเอง และล้างข้อมูลเก่าที่อาจค้างจากเวอร์ชันก่อนหน้าโดยอัตโนมัติ ข้อมูลที่นำเข้าจะอยู่ในแท็บเบราว์เซอร์นั้นเฉพาะช่วงใช้งานเท่านั้น เว้นแต่จะเลือก **"บันทึกในเครื่องนี้"** (เก็บใน `localStorage`) หรือ **"ดาวน์โหลดข้อมูลสำรอง"** (ไฟล์ JSON ที่เก็บเองได้) จากแท็บข้อมูลและสำรอง
- รหัสผ่านทั้ง 4 บทบาทถูกแฮชก่อนเก็บ แต่ตัวข้อมูลยอดขาย/ลูกค้าที่นำเข้าเองถูกเก็บในรูปแบบข้อความธรรมดาในพื้นที่เก็บข้อมูลของเบราว์เซอร์ — การป้องกันด้วยรหัสผ่านเป็นการกันการเข้าถึง ไม่ใช่การเข้ารหัสข้อมูล ผู้ที่เข้าถึงโปรไฟล์เบราว์เซอร์นั้น (หรือไฟล์สำรอง JSON ที่ดาวน์โหลดไว้) จะอ่านข้อมูลจริงได้

## 7. ข้อจำกัดที่ทราบ

- **การคาดการณ์รายสินค้า (SKU) ยังไม่น่าเชื่อถือ** (ค่าคลาดเคลื่อนวัดได้ประมาณ 78%) และแสดงเป็นเพียงตารางอ้างอิงที่ระบุไว้ชัดเจน การตัดสินใจควรใช้การคาดการณ์ระดับกลุ่มแทน
- **ยังไม่มีการนำเข้าข้อมูลสต็อกจริง** วันที่สต็อกพอใช้ในมุมมองสินค้าขายดีมาจากตัวเลขที่พิมพ์เองต่อกลุ่มเท่านั้น ไม่ได้ตรวจสอบกับยอดสต็อกจริง และจะรีเซ็ตเมื่อโหลดหน้าใหม่หรือปิดแท็บ
- **ประวัติข้อมูลยังสั้น** ข้อมูลจริงชุดปัจจุบันมีน้อยกว่าหนึ่งปี ซึ่งพอสำหรับช่วงคำนวณแบบหมุน 3–6 เดือนที่ใช้อยู่ แต่ยังไม่พอเปิดใช้ฤดูกาลตามเดือนปฏิทิน (ต้องการประมาณ 12–24 เดือน) — แอปจะบอกตรง ๆ แทนการเดารูปแบบฤดูกาลที่ยังไม่มีข้อมูลรองรับ
- **ชื่อกลุ่มสินค้ายังเป็นการชั่วคราว** วิเคราะห์อัตโนมัติจากรหัส 2 หลักแรกในไฟล์ที่นำเข้า กลุ่มใดที่ไม่อยู่ในตารางชื่อในตัวจะแสดงหมายเหตุ "รอการยืนยัน" แทนการตั้งชื่อเอาเอง
- **ลูกค้าฝั่งขายเงินเชื่อไม่มีรหัสลูกค้า** ในไฟล์ส่งออกจาก Express (มีแต่ชื่อ) จึงอาจจับคู่กับลูกค้ารายเดียวกันในฝั่งขายเงินสดโดยอัตโนมัติไม่ได้เสมอไป
